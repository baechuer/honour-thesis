## Purpose

RQ1b v2 and v2.1 remain frozen, completed public-card evidence. V3 is a
separate prospective expansion with two deliberately distinct assets:

1. a large, versioned, hash-deduplicated **public skill source frame**; and
2. a strict, much smaller **near-neighbour cluster cohort** curated from that
   frame for a later source-grounded field-card replication.

The source frame measures what can be recovered or co-occurs in a defined
public-artifact collection. It is not a selector benchmark. The cluster cohort
tests strict routing among three or four semantically close public skills. It
is not a prevalence sample of all skills.

The seven operational fields retain their existing basis in the RQ1 conceptual
framework and controlled RQ1a experiments. A large corpus audit may support
their public recoverability and co-occurrence; it must not claim to have
discovered, proven, or universally ranked the taxonomy merely by counting
headings in all local files.

## Why A New Source Frame Is Necessary

The workspace contains many paths named `SKILL.original.md`, but raw path
counts include staged-source mirrors, packet copies, historical snapshots,
quarantine material, outputs, and synthetic RQ2 overlays. They must not be
misreported as distinct public skills. V3 therefore begins with canonical
source provenance and exact content hashes, not a path-count claim.

## V3 Source-Frame Inclusion Rules

A canonical V3 source record must satisfy all of the following:

1. It is an available local original public skill artifact, normally an
   upstream `SKILL.original.md` or a source-pinned equivalent.
2. Its origin root, local source path, source hash, byte count, and discovery
   lineage are recorded.
3. Exact duplicate bytes are represented once as one canonical artifact; all
   duplicate paths remain aliases/provenance and may not be separate cluster
   candidates.
4. It is not a generated RQ2 overlay, benchmark-controlled skill, output
   payload, cache, quarantine copy, packet mirror, test fixture, or
   unresolved source artifact.
5. A source root may contribute many candidate artifacts, but an eventual
   V3 strict candidate composition uses distinct canonical artifacts and
   preserves source-provenance/cue-risk control.

The first local pass may use only already staged source roots. Any later web
discovery must create a separate dated source batch with pinned root/revision,
download audit, and deduplication against the frozen local frame; it must never
silently alter an already frozen V3 source manifest.

## Large-Corpus Audit Boundary

After the canonical source frame is frozen, the audit has two layers:

| Layer | Unit | Permitted output | Not permitted |
|---|---|---|---|
| Deterministic structural census | Every canonical artifact | lengths, headings, explicit labels, tool/code/link patterns, exact duplicate rate, source-origin strata | semantic proof that a field is present merely because a heading exists |
| Calibrated recoverability audit | Stratified sample of canonical artifacts | explicit/implicit/absent evidence, field co-occurrence, evidence location and extraction ambiguity | human-prevalence or universal-field claims when the audit is model-assisted only |

Any thesis wording must therefore be: “in the declared, snapshot-dated,
hash-deduplicated public source frame, operational evidence was recoverable at
the reported rate.” It must not be: “we examined every public skill” or “the
fields were induced from all skills.”

## V3 Cluster-Discovery Rules

The discovery population is the canonical source frame, not the raw paths.
Automated discovery may use lexical/task fingerprints to find candidate
neighbours, but it produces drafts only. A strict V3 composition must pass:

1. three or four distinct canonical public artifacts, preferably across source
   origins, with no alias/byte duplicate;
2. a common broad task envelope and plausible semantic confusion, but a real
   operational difference in source evidence;
3. one strict gold candidate for a source-informed direct prompt and an
   intent-preserving paraphrase;
4. source-name, URL, repository, and copied-heading cue control in the later
   card representation;
5. two independent selection-only reviews of the `FULL` source-grounded field
   cards. `MULTIPLE_ADEQUATE`, `NONE_ADEQUATE`, reviewer disagreement, or
   unsafe source-card construction excludes the family from strict Top-1;
6. source hash, prompt, cue risk, card evidence, candidate membership, and
   exclusion rationale frozen before any selector scoring.

V3 targets **at least 100 frozen candidate compositions**, not an inflated
count of prompts or mask rows. Discovery deliberately over-recruits; no target
yield is assumed before the gates finish. The existing cross-source curation
pool is an input to this process, not an automatically scoreable V3 cohort.

The lexical C0 path is a feasibility audit, not the only permitted discovery
path. A prospective `D1` directed public-source discovery amendment is recorded
in `thesis_notes/archive/RQ1/superseded-public-card/RQ1b V3 D1 Directed Public-Source Discovery Amendment - 2026-08-29.md`.
It changes discovery priority only and must report its screening counts
separately; all C1--C6 strict gates remain unchanged.

## C1 Source-Evidence Card Gate

C1 is still source-only and has a narrower purpose than the later strict-gold
gate: it determines whether a C0 advance has sufficient exact, natural-source
evidence to justify prompt design. It must not create a prompt, intended
winner, gold label, acceptable set, field mask, representation, selector input,
or metric.

For each of the three canonical source artifacts, a C1 card records:

1. the candidate's source title and immutable source ID/hash;
2. a short common-envelope statement grounded in all three sources;
3. one exact source span for its primary input/precondition or trigger;
4. one exact source span for its operation/procedure and expected output;
5. one exact boundary, prerequisite, dependency, or explicit route-out where
   present; and
6. an evidence-based explanation of why the candidate is a peer route, rather
   than a lifecycle stage, generic fallback, wrapper, parent/container,
   implementation component, duplicate, or merely a different interface.

A C1 composition advances only when every member has a source-grounded
input-to-operation-to-output chain and the three chains remain plausibly
competitive under one broad envelope. If a source card reveals containment,
overlap, insufficient contrast, an absent operational chain, or a source-span
binding failure, the composition is rejected at C1. A C1 pass is still not a
strict cluster: C2 will build a direct prompt and an intent-preserving
paraphrase; C3 will control literal cues; C4 will obtain two independent
selection-only singleton reviews; and C5/C6 will freeze only the surviving
families.
