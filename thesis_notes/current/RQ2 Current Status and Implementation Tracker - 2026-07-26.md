## 6. RQ2a Representation Conditions

The former `I1-controlled` and `I3-oracle-*` labels are retired. RQ2a uses treatment names that state what changes.

The comprehensive specification contains a worked `ip01_pdf_scanned_tables` example for every representation.

### Representation implementation pass

A representation family is `IMPLEMENTED` only when:

- every selected cluster and candidate has exactly one row;
- `cluster_id`, `skill_id`, role, source path, and representation label align;
- fielded, flat, prose, order, and diluted variants preserve the reviewed propositions;
- no selector-visible text contains gold/alternative labels;
- controlled names are neutral;
- padding is byte-identical among siblings and contains no decisive/leakage term;
- token and character counts are recorded;
- source, serializer, and output hashes are stored;
- a human-readable sample report shows at least one cluster per field.

## 8. Existing Versus Required Field-Aware Selector

The repository already contains two field-aware prototypes:

| Prototype | What exists | Why it is not the clean RQ2a selector |
|---|---|---|
| `M6-v1` | Lexical field-aware reranking over persisted first-stage candidates in `skill_benchmark/scripts/run_m6v1_field_aware_reranker.py` and `skill_benchmark/scripts/field_aware_matching.py`. | Lexical/cue-driven, coupled to old R1/R2/R3 artifacts and a first-stage score. |
| `M6-v2` | Qwen semantic comparison of parsed request fields against separately embedded candidate fields in `skill_benchmark/scripts/run_m6v2_semantic_field_reranker.py`, with field weights, boundary penalties, and first-stage blending. | Uses the old frozen-v0.4 pipeline, calibrated weights, request parsing, selected field sets, and first-stage blending. It excludes success/verification from its current main positive-field implementation and is not a same-facts fixed-candidate test. |

Therefore the new method is an **adaptation**, not a from-scratch invention.

### Implemented RQ2a field-aware selector

The RQ2a adapter now:

1. read `same-facts-fielded` directly;
2. embed each of the seven fields separately;
3. embed the raw user query without using the benchmark's target-field label;
4. score all three candidates directly, with no first-stage score or candidate exclusion;
5. use no gold, role, cluster-field, or alternative metadata;
6. return candidate score, per-field component scores, chosen candidate, rank margin, and latency;
7. cache every unique query and field embedding;
8. apply one frozen, target-agnostic aggregation rule to every field suite.

Candidate aggregation rules implemented for development-only comparison:

- maximum field similarity;
- uniform top-two average field similarity.

The complete 70-cluster development set selected and froze `uniform-top-two`. The 7-cluster smoke did not determine this choice. Field-specific weights, target-field oracle scoring, and confirmatory-set tuning remain prohibited.

### Field-aware mechanism comparisons

| Comparison | Isolated interpretation |
|---|---|
| `same-facts-flat + Qwen single-vector` vs `same-facts-fielded + Qwen single-vector` | Effect of labels and boundaries under the same generic selector. |
| `same-facts-fielded + Qwen single-vector` vs `same-facts-fielded + field-aware Qwen` | Effect of explicitly using field boundaries while facts and embedding provider remain fixed. |
| `same-facts-flat + Qwen single-vector` vs `same-facts-fielded + field-aware Qwen` | Combined representation-plus-selector system effect; not a single-factor causal comparison. |

## 12. Scientific Outcome Criteria

These criteria evaluate evidence, not software correctness.

Suggested smallest effect of practical interest: **3 percentage points in paired top-1**, pending supervisor approval before protocol freeze.

| Claim | Evidence that supports it | Null/negative interpretation |
|---|---|---|
| Explicit field organisation helps a generic semantic selector. | `same-facts-fielded - same-facts-flat >= 3pp`, primary 95% CI excludes zero under Qwen. | Facts matter more than literal labels, or single-vector embedding cannot exploit the structure. |
| Organisation effect is robust across selector families. | Same direction under BM25 and cross-encoder, with at least one replication CI excluding zero. | Effect is selector-specific; report interaction rather than a universal gain. |
| Field-aware use adds value beyond merely showing labels. | `field-aware Qwen - single-vector Qwen >= 3pp` on `same-facts-fielded`, with paired CI excluding zero. | Explicit segmentation does not improve this selector, or aggregation is not adequate. |
| Information dilution harms selection. | Accuracy/margin decreases as shared padding increases, with a practically meaningful 0x-to-4x decline. | Added support text is not the bottleneck for the tested selector and length range. |
| Reasoning helps conditional fields. | Cross-encoder or LLM gains are concentrated in boundary, success, and workflow suites. | Conditional fields remain intrinsically difficult, or the reasoning method does not use them reliably. |
| Operational facts remain necessary. | Same-facts representations outperform `shared-only`. | A failure here indicates a runner, prompt, or representation problem because RQ1 already established the facts' controlled value; investigate before interpretation. |

No representation is required to win for the study to “pass”. A credible null result with passed controls answers the mechanism question.
